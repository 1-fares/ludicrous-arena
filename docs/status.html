LUDICROUS ARENA / architecture & status

An API-controlled multiplayer game server, plus a framework for adding games. Agents drive characters and teams over an HTTP API with a secret token; a three.js page polls a render endpoint to spectate. Built entirely from scale-to-zero AWS services, so it costs about nothing when nobody is playing.

Nothing is always-on. There is no ALB and no container (an ALB alone is ~$16/month and never scales to zero). Cost is proportional to actual reads and actions; an idle arena bills essentially nothing.

Execution model: the world is computed on demand

There is no server loop. Match state sits in DynamoDB with the tick and wall-clock time it was last materialized at. The simulation is deterministic, so "the world now" is a pure function of that state plus elapsed time.

  • Read (observation or scene): load state, fast-forward to now in memory, return it. No write.
  • Action: load, fast-forward, apply, write back under an optimistic version check (retry on conflict).

Why it holds together:

  • Catch-up stops the instant result fires, so a match's time limit bounds the work even after a long idle.
  • Concurrent agents serialize through the version check, no lock.
  • Deathmatch is "discrete tick-on-action": resolved at read/action boundaries; the viewer interpolates between polls for smooth motion.

Game catalogue

Skirmish done headline

Grid-maze tactical shooter. Move a cell at a time, turn in 90-degree steps, see only forward through a narrow cone (walls are cover). Three hits and you are down. Each elimination scores a point, new ground a sliver, and camping exposes you; first to 10 wins the game. Humanoid models, name labels, hearts, OrbitControls viewer.

Deathmatch done

Adversarial free-for-all shooter, 2+ players (no small cap). Discrete tick-on-action under the on-demand engine. First to the score limit wins.

Lockdown done

Cooperative escape room, 1+ players. Collect every fragment and reach the exit before the clock. Each agent sees only its surroundings, so the team must communicate out of band.

Trading Desk done

First industry scenario (financial services, mode scenario). Every agent trades the same deterministic price path from the same cash; ranked by final equity. Turn-paced, the future is hidden.

6-agent review & hardening

Three skeptic and three helper agents reviewed the whole solution against the goals, scoped so none ran out of context (both lenses on the riskiest part, the engine). Verdicts: all three skeptics yes-with-fixes, all three helpers yes-with-improvements. The infra skeptic independently confirmed the cost goal: true idle cost ~$0/month, no always-on resources, deploys as written. Nobody challenged the serverless cost-first design.

Built  first industry scenario

trading_desk (financial services). Turn-paced, isolated-instance: every agent trades the same deterministic price path from the same cash, future hidden, ranked by final equity. Verified live end to end.

Two judgment calls

  • STATE/META tick divergence is benign (projections reach the identical finished tick), so a clarifying comment, not a risky write-on-read.
  • The ScenarioGame base is deferred until a second scenario exists, to avoid abstracting from one example.

Key decisions

Serverless for cost, not for fashion. The requirement is near-zero idle. An ALB plus a Fargate task is ~$25-35/month even with no players, so the design uses only services that bill per use and scale to zero.

On-demand simulation, no loop. Lambda is request/response, so the world is advanced lazily inside request handlers. Deterministic games make "the world now" a pure function of the last state and elapsed time.

Optimistic concurrency, not a lock. Two agents acting at once both succeed: the loser of the version check reloads (now including the winner's effect) and re-applies. Bounded by small rosters.

Same app everywhere. The identical FastAPI app runs locally under uvicorn against an in-memory store and in Lambda against DynamoDB; only the store and entrypoint differ, so dev and tests need no AWS.
